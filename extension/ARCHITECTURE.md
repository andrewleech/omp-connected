# Architecture

The extension connects directly to omp-hub's `/ws/agent` WebSocket, JSON-RPC 2.0 framed like `/ws/host`. omp-hub is the sole authority for agent identity, routing, teams, and mailbox state — no claude-net dependency of any kind, not source, not runtime. Canonical identity is `${hostId}:${instanceId}`, where `hostId` matches `bin/omp-host`'s own `${user}@${hostname}` and `instanceId` is the session's real Collab instance id, discovered at runtime via `@oh-my-pi/pi-coding-agent/collab/registry`'s `listCollabHosts()` (OMP exposes no direct `instanceId` accessor). The hub cross-validates every registration against the owning host's live `collab.list` before admitting it, closing the impersonation window a self-reported or cached identity would leave open. Inbound frames are converted to OMP `role:"custom"` messages with agent attribution and a model-visible untrusted-origin prefix.

Registration is automatic, not tool-driven: it starts on `session_start`, polls the local Collab registry for up to 10 seconds for this process's own PID to appear (registry publication happens asynchronously after the relay connects, so it may not be there yet at extension-init time), then registers with exponential backoff (1s-30s, jittered) on failure or disconnect. There is no `session` string parameter and no free-text identity generator anymore — the identity is entirely server-derived from the registration result, exposed read-only via the `ompc_identity` tool. `agent.send`/`agent.send_team` carry a client-supplied idempotency key that is retried verbatim (not regenerated) across a dropped connection, so a message is delivered at-least-once without becoming at-least-twice.

`ompc` is intentionally outside the extension process. An extension ends when OMP ends, so it cannot provide detach or reattach. The launcher gives every OMP session its own GNU Screen server and does not use tmux or OMP's broker. It starts detached Screen servers with closed standard streams so the invoking process does not retain a terminal pipe. The bundled Screen configuration supplies the terminal contract for the OMP TUI. `ompc` is the single entry point for interactive use: it creates a Screen session named after the current working directory (optionally suffixed) when none exists, or reattaches to a matching one, either way launching OMP inside it with any other arguments forwarded verbatim. The `collab` subcommand is the one exception: it bypasses Screen entirely and runs OMP directly, since automation -- in particular `bin/omp-host`, which invokes the configured `OMP_COLLAB_BIN` with `collab ...` -- must never attach a TUI. Do not alias or install `ompc` as `omp`: that name is the official oh-my-pi CLI entrypoint, and this plugin must never shadow it.

GNU Screen filters raw OSC 52. The version-pinned OMP patch wraps an explicit copy action in a DCS pass-through envelope when `TERM` starts with `screen`, preserving OSC 52 through Screen and SSH. The launcher runs the patched TypeScript CLI entry point through Bun because npm's pre-bundled executable cannot consume a source-only dependency patch. `OMP_BIN` replaces that default for a separately built binary containing the same change.

The browser dashboard and Collab relay integration are separate omp-hub deliverables; this extension does not serve browser traffic or relay Collab ciphertext.

`bin/omp-host` is the host-side sidecar for the dashboard broker. It maintains a `/ws/host` connection to omp-hub and invokes OMP's supported local `collab list` and `collab link` commands only when the hub requests them. The registry remains private to the local OMP user. A returned link is a generation-bound bearer capability and is forwarded in memory only; it is not published as a dashboard event or retained by the daemon.
